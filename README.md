# txxprd

按现有模板编写、更新和评审飞书 PRD 的 AI 技能包。支持功能说明表、飞书画板流程图、原型截图、验收标准，也支持根据评论修改正文，或只在文档中留下评审意见。

> 适用于 Codex、WorkBuddy、Claude 等支持 Skill 的 AI 助手。基于官方 [lark-cli](https://github.com/larksuite/cli) 的文档块与评论接口。

## 它能做什么

| 能力 | 说明 |
|---|---|
| 标题层级 | 分区使用真实标题并逐级编号，如 `5.1 → 5.1.1 → 5.1.1.1`，写后核对文档大纲 |
| 功能说明表 | 沿用作者示例；分层编号、一条一规则，精简表达并保留条件及异常 |
| 产品流程图 | mermaid 一键转飞书**原生画板**（节点可编辑，不是图片） |
| 交互原型图 | 功能表嵌入对应截图；按需插入 HTML 附件，验证切换后的共享区域和输入保留 |
| HTML 附件预览修复 | 在实际预览中复现校验、提交、存储与布局问题，检查改填、失败重试、键盘提交及小屏滚动 |
| 验收标准 | 按页面或功能分组并关联功能说明，写清前置条件、操作及结果，支持原生可勾选清单 |
| 按评论修订 | 读取评论与回复，定位对应段落，局部修改并逐项核验 |
| 文档评审 | 在指定块留意见，保留正文；仅要求给建议时在当前对话反馈 |
| 权限诊断 | 区分账号、应用、登录、API 授权及资源访问权，按任务申请最小权限 |
| 设计规范对齐 | 先读 MasterGo 设计规范、After / V2 画板和同模块状态，再制作 HTML 与截图 |
| 图层独立与来源边界 | 来源页面只读；复制到目标后形成独立图层，回读目标并检查灰色占位、外部引用和清理条件 |
| 真实入口交互 | 从真实页面入口逐层点击到弹层、编辑、取消和结果，不以下拉状态或截图代替交互 |
| 多版本同步 | 业务规则、MasterGo、HTML、截图、飞书图片和附件按依赖顺序更新，并分别留证 |
| 写入验证 | 写前留存旧值；表格记录必须入格；每次写后回读结构并检查网页排版，修复出格、错列和编号异常 |

## 安装

```bash
# Codex：安装到尚不存在的技能目录
git clone https://github.com/mastarai2024-del/txxprd.git ~/.codex/skills/txxprd

# WorkBuddy：选择对应环境执行
git clone https://github.com/mastarai2024-del/txxprd.git ~/.workbuddy/skills/txxprd
# 项目级安装：放到 <项目>/.workbuddy/skills/txxprd
```

## 使用

直接对助手说：

- 「把这段规则写进 PRD 的功能说明里」
- 「产品流程图更新到文档的画板里」
- 「换一版交互原型图，同步更新文档里的图」
- 「这份 PRD 的 HTML 附件无法正常交互，先复现问题，再修复并同步截图和附件」
- 「按我在这份 PRD 的评论修改正文，先保留评论状态」
- 「审阅这份 PRD，在有问题的段落留评论，不改正文」

提供真实文档链接及具体任务。技能按请求选择正文编辑或评论评审流程；已有明确授权的普通操作连续执行，缺少必要信息或遇到真实权限阻塞时说明原因。

## 环境自举（新电脑，无需预装飞书套件）

技能随附基于飞书套件 v2.3.0 的参考与自举脚本（`vendor/lark-unified/`），已补充部分新版本兼容说明：

```bash
# 1. 在技能目录检查（exit 0=配置存在 / 3=未安装 / 4=未配置 / 5=输出异常）
python3 vendor/lark-unified/scripts/lark_status.py --json

# 2. 未安装则安装（需 Node 18+，约几分钟）
npx -y @larksuite/cli@latest install

# 3. 按 references/auth-and-diagnostics.md 核对身份并按需授权
```

配置成功不等于用户已登录或目标文档可编辑。CLI 1.0.90 的裸 `auth login` 会请求所有已知业务域权限；本技能使用明确的最小 `--scope` 和分回合授权流程，不要求为编辑正文申请整份文档删除权限。凭证由 CLI 在本机管理，不写入技能文件或仓库。

## 首次配置

1. 对话中给出目标文档链接；以本次指定的目标为准，无需修改全局技能来绑定某一份 PRD。
2. 将 `references/project-context.md` 复制到项目的私有目录，维护术语、模板及本地资产。真实文档内容、评论快照、身份信息和回执留在本机，不提交公开仓库。

## MasterGo 设计与 MCP

当项目使用 MasterGo 作为设计源时，Codex 配置：

```toml
[mcp_servers.mastergo]
command = "npx"
args = ["-y", "@mastergo/vibe-mcp@1.0.31", "--url=http://localhost:30678"]
```

开始任何设计图、截图或 HTML 原型前，先读 [`references/design-system-and-mastergo.md`](references/design-system-and-mastergo.md)，并在 MasterGo 中确认：

1. 「设计规范」画板及节点 ID。
2. 最终版 After / V2 画板及节点 ID。
3. 同模块其他弹窗、表单、按钮和空状态。
4. 明确排除 Before 和旧版画板。

把结果写入项目私有 `design-baseline.md` 后再开始设计。MCP 只连接当前 MasterGo 打开的文件；调用工具时传项目绝对路径作为 `projectDir`。

MasterGo 任务还必须明确唯一写入范围。来源页面、设计规范和旧版稿默认只读；从来源复制到目标后，图片要成为目标文件内的独立图层，不能依赖 `revisionId` URL、临时本地地址或 `data:image`。接口返回 accepted 后要重新读取目标节点并用原生截图验收，后台完成前不报告完成。

## 技术要点（踩过的坑，都写在技能里了）

- 上传图片必须用 `<img path="@./本地图"/>`；用 `src=token` 复制会把元数据写脏
- 整表重建用 `block_replace` + colgroup，写后检查高亮、列宽与媒体是否保留
- 画板预览按工具要求导出为 jpg；结构修改后重新 fetch 再使用 block id
- 新的复杂写法先在获准的测试文档验证；普通文字修订做针对性回读
- 简化表格优先改目标单元格内的文本块，回读比较未涉及列和资源；避免为改文字重传图片
- 文档版本、原型版本分别记录；需求范围按端及职责填写，章节按本次要求取舍
- 原型状态、最终附件、流程节点可编辑及实机后台能力分别验证；截图失败时说明视觉检查限制
- 评论按真实 block 定位；任意文字范围的精准划词与 Markdown 格式无损转换需另行验证
- `render-html.cjs` 依赖 `puppeteer-core` 和 macOS Google Chrome，其他环境需适配浏览器路径
- 设计前必须读 MasterGo 设计规范与 After / V2 画板；只改按钮颜色不等于完成设计对齐
- 设计规范与页面实际值冲突时先记录并确认，不静默创造规范外字号或圆角
- HTML 附件替换后要下载比对 SHA-256；同一 token 的 CDN 缓存可能短暂返回旧内容
- 批量替换飞书图片前先冻结 HTML 和全部截图；替换后不要再改 CSS
- 画板导出缺少 `board:whiteboard:node:read` 时按最小 scope 授权；应用后台未开放时不能靠重复登录解决
- MasterGo 来源页面默认只读；复制后回读目标，确认图片没有灰框、外部 URL、临时地址或未解绑实例
- accepted / queued 只是受理状态；必须等后台处理结束后重新读取节点，再按画板尺寸做截图验收
- 一个状态可能同时出现在总览表、功能表和正文中；统一搜索引用位置，避免只换一处留下旧图
- 真实入口和结果路径要实际点击；触摸左滑、后台续传和真实设备能力未验证时单独标注

## 文档格式与界面修订

- 二级标题内还有独立标题时，使用编号三级标题；继续细分时依次增加标题级别和编号深度。
- 版本日志、功能表等已有表格中的记录写入对应行和单元格，不能在表格外追加文字代替新增行。每次写完检查大纲、表格结构及飞书网页显示。
- 用户界面说明写具体效果；只读字段使用普通文本，保留原权限与对象范围。修改后同步受影响原型、配图及验收项。
- 详细例子与检查步骤见 [PRD 写法与交付检查](references/prd-authoring.md)。这些规则不规定业务页面数量、阈值或设备权限。

## HTML 附件预览修复

本地能打开的 HTML，在飞书附件预览中仍可能遇到表单、存储或视口限制。技能按实际环境排查，不把所有“按钮没反应”归因于同一种问题：

| 现象 | 排查与验收重点 |
|---|---|
| 点击保存后停在原页 | 区分输入校验、提交处理和保存结果；保留业务校验，检查改填后旧错误是否更新 |
| 点击与 Enter 的结果不同 | 确认宿主限制后统一客户端提交处理，避免重复保存或跳转 |
| 重绘、弹层或返回后输入丢失 | 按账号、设备和表单范围保留所需草稿；敏感字段不写入持久存储 |
| 预览不允许本地存储 | 本次会话仍可操作，提示刷新后进度不保留；不同原型隔离存储键 |
| 窄屏内容过长或按钮不可达 | 在实际手机视口检查内部滚动和底部操作区，区分视口坐标与文档坐标；长截图单独用于文档展示 |
| 图片刚出现时是占位 | 等实际显示图加载完成后再判断缺图，并目检内容 |

修复后，在**当前云端附件**中走通“非法输入 → 改正 → 保存失败 → 重试成功”，并检查点击和 Enter 提交。同步更新受影响的截图与附件，下载比对资源哈希；模拟接口与真实服务仍分别记录验证状态。

具体步骤见 [受限预览中的交互修复](references/prd-authoring.md#受限预览中的交互修复)。
